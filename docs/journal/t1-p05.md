# t1-p05: Phase 5: Ingesting from several sources into bronze, silver and gold

## Built
Three sources flowing into layered Iceberg tables, all jobs writes-by-table-name only (no hardcoded
S3 paths). **Sources stack** (core): `platform/compose.sources.yaml` adds `source-db` (Postgres 17,
`ops`/`ops`, data in `${PG_ROOT}/source-db`, init script `platform/conf/source-db/01-schema.sql`
creating `taxi_zones`). **Files source**: `scripts/download_tlc.sh` pulls monthly NYC yellow-trip
Parquet into `${DATA_ROOT}/landing/tlc/yellow` (host-mounted at `/data/landing` in every Spark
container); `pipelines/jobs/ingest/tlc_bronze.py` casts every file onto one canonical 19-column
schema (lowercase name map, missing columns → NULL), adds `_source_file` (from
`_metadata.file_path`), `_ingest_month`, `_ingested_at`, and writes
`lake.bronze.tlc_yellow` partitioned by `_ingest_month` — `create()` first, `overwritePartitions()`
on rerun. **JDBC source**: `pipelines/jobs/ingest/zones_from_pg.py` reads
`public.taxi_zones` over JDBC (password from `SOURCE_DB_PASSWORD` env, already wired into the
Spark services in t1-p02) and upserts `lake.silver.zones` via `MERGE` guarded by `updated_at`.
**REST source**: `pipelines/jobs/ingest/weather_bronze.py` calls open-meteo's archive API from the
driver, hands the pandas frame to Spark (Arrow) and (re)creates `lake.bronze.weather_hourly`.
**Silver**: `pipelines/jobs/transform/trips_silver.py` cleans one month (drops mis-dated rows,
non-positive distance, negative total, dropoff-before-pickup, duplicates) into
`lake.silver.trips` partitioned by `days(pickup_ts)`. **Gold**:
`pipelines/jobs/transform/daily_zone_weather.py` rebuilds `lake.gold.daily_zone_weather`
(trips/revenue/tip-ratio per borough-day joined to daily weather, partitioned by `months(day)`).

## Deviations from the tutorial
What differed, why, and the error that forced it.

1. **The landing subdirectory needed owner-side host prep (one time).** The tutorial's verify runs
   `scripts/download_tlc.sh` on the host, but `/lake/lakehouse/landing` is root-owned (prepared in
   t0; Spark containers only read it). `mkdir -p` as `praneet` failed with `Permission denied`.
   Host filesystem prep is owner-only per the working agreement, so the owner ran
   `sudo mkdir -p /lake/lakehouse/landing/tlc/yellow && sudo chown -R praneet:praneet
   /lake/lakehouse/landing/tlc`. Recorded under Needs owner action (resolved).
2. **`trips_silver.py` gained one line: `CREATE NAMESPACE IF NOT EXISTS lake.silver`.** The
   tutorial's job omits it, and its own verify order runs silver (in the per-month loop) before
   `zones_from_pg.py` — so the very first silver run failed with
   `NoSuchNamespaceException: Namespace does not exist: silver` (Iceberg REST, Polaris). Added the
   namespace creation exactly as the tutorial's own `tlc_bronze.py` and `zones_from_pg.py` do.
   No other change.
3. **Ruff-driven import formatting (carried forward from t1-p04).** `import argparse, sys` and
   `import pandas as pd, requests` split (E401), and the `pensieve` import sorted before
   `pyspark` (I001 — ruff wants alphabetical order within the post-`sys.path` block). No
   behaviour change.
4. **`scripts/download_tlc.sh` loads `.env` when `DATA_ROOT` is unset.** The tutorial runs the
   script directly, but with `set -u` and no exported `DATA_ROOT` it dies on
   `DATA_ROOT: unbound variable` (or, worse, would target `/landing` silently without `-u`).
   The script now sources `.env` from the repo root when `DATA_ROOT` isn't already set, and fails
   loudly if neither exists. Same convention as `./dc`.
5. **`spark.stop()` added at the end of each job.** The tutorial's jobs omit it; the reviewed
   `row_count.py` from t1-p04 has it. Consistency; drivers otherwise exit via shutdown hook anyway.
6. **Explore harness notes (not repo changes):** `--conf spark.jars.ivy=/tmp/ivy2` for any
   `--packages` run in the `spark-client` image (Ivy cache under `HOME=/nonexistent` is unwritable;
   `HOME` override doesn't work — see Explore), and `spark-sql` invoked directly rather than
   through `lake-submit`.

## Findings
Anything worth remembering: surprises, measurements, ideas for later.

- **No schema drift in the 2024-01…06 window**: all six files have identical column names, cases
  and types. The canonical map still earns its keep via case-mapping (`Airport_fee`,
  `RatecodeID`, …) and will matter for other months/years; re-check when ingest widens.
- **Raw data quality is poor in the timestamp columns**: pickups as early as 2002 and dropoffs as
  late as 2026 exist inside the 2024 files. Silver's
  `date_format(tpep_pickup_datetime, 'yyyy-MM') == month` filter dropped 599,356 rows (2.95% of
  raw). This is exactly the "mis-dated rows" case the tutorial warns about.
- **silver.trips is already a small-file case**: 182 day-partitions, avg 1.67 MB/file, vs bronze's
  single 50 MB file per month. `rewrite_data_files` in Phase 8 has an obvious target here.
- Gold has 1,418 rows = the borough-day combos that actually have trips (182 days × 8 boroughs
  would be 1,456; 38 combos are trip-less — mostly EWR/Staten Island days).
- **Polaris REST metrics-reporter noise**: on the *first* commit of a table's life, Iceberg's
  `RESTMetricsReporter` POSTs a report before the table is visible and logs a 404
  (`NoSuchTableException`) stack trace, then retries and succeeds (seen on `weather_bronze` and
  the first bronze run). Harmless, but don't mistake it for a failed write — check for the
  `CommitReport`/`Committed in` lines instead.
- `make s3` mounts only `$(PWD)` into the aws-cli container, so it cannot reach
  `/lake/lakehouse/landing` for host-side uploads; the explore upload used the same aws-cli image
  with the landing volume mounted at `/landing`. (Also: pass `-e AWS_ACCESS_KEY_ID="$S3_ACCESS_KEY"`
  explicitly — `.env` defines `S3_*`, not `AWS_*`.)
- Timings on the small shape (16-core cap): bronze/silver ~19–24 s wall per month (3–3.7 M rows),
  zones MERGE 13.3 s, weather 13.6 s, gold rebuild 18.3 s; the per-submit floor is the container +
  JVM boot (~10 s).
- The owner's untracked `notebooks/demo/querying_*.ipynb` (enwiki clickstream exploration) were
  left untouched and uncommitted — not part of this phase.
