## Deviations from the tutorial
What differed, why, and the error that forced it.

1. **`CLAUDE.md` omitted by owner decision.** Step 2 says to `ln -s AGENTS.md CLAUDE.md`, but the owner does not use Claude Code and left it out deliberately. The Step 2 Verify command `ls -l CLAUDE.md` therefore fails. With the owner's approval this PR also removes the `CLAUDE.md` references from `README.md` and `docs/tutorials/0-setup.md` (repo-layout comment, Step 2 build instruction and bash block, Step 2 Verify bullet). The owner's later manual re-edit of the tutorial (the storage rework, made against an older copy) restored those references; they were removed again in this commit.
2. **`uv` and `pre-commit` were not installed on the host.** Step 1 Build lists them, but only `git`, `gh`, `gettext-base`, `jq` and `numactl` were present; `pre-commit install`, `autoupdate` and `run --all-files` could not run (`zsh: command not found: pre-commit`). Installing host packages is owner-only, so the owner was asked and installed them mid-phase: `uv 0.13.6` (astral.sh installer, `uv tool install pre-commit`) and `pre-commit 4.7.0`. Everything then proceeded as written.
3. **Storage tiers reworked after the fio baseline (owner).** The Step 1 Explore fio tests showed the 477 GB PNY SSD sustains only ~72 MB/s writes even after a full TRIM — too slow for Postgres and Kafka. The owner redesigned the tiers: the `hot` ZFS pool is dropped, Postgres/Kafka move to the root NVMe under `/srv/pensieve` (`PG_ROOT=/srv/pensieve/postgres`, later `KAFKA_DATA=/srv/pensieve/kafka`), and the PNY becomes an L2ARC read cache for `lake`. The owner updated `docs/tutorials/0-setup.md` themselves; this commit patches the matching references — `.env.example` (`PG_ROOT`), tutorial 2's Kafka paths — and creates `docs/benchmarks.md` with the measurements. The host rewire is owner-only (`zpool destroy` is destructive); the owner executed it the same day and the reworked Step 1 storage Verify passes (final table above).
4. **Owner-directed squash of the PR.** The owner asked for the doc rework to land inside the single phase commit, so the branch will be amended and pushed with `git push --force-with-lease` — normally an owner-only, destructive action, done here on the owner's explicit instruction. PR #1 stays open and shows one commit.

### Storage rework and fio baseline (owner, 30 Oct 2026)
- Measured: scratch XFS 533 MB/s seq write / 73.6k IOPS 4k randread; PNY 477 GB (ZFS 16K records) 72 MB/s sustained / 4.9k IOPS; lake HDD (ZFS 1M records) 203 MB/s / 108 IOPS. Full table in `docs/benchmarks.md`; Tutorial 1's Phase 7 compares Spark stage times against it.
- The PNY's ~70 MB/s sustained after TRIM killed the `hot`-pool plan: small synced writes (Postgres, Kafka) go to the root NVMe, and the PNY serves as the lake's L2ARC, where it is ~45x faster than the HDD at random reads and losing it costs nothing.
- `.env.example`'s `PG_ROOT` changed from `/hot/lakehouse` to `/srv/pensieve/postgres` to follow the reworked tier table — the only edit to a file this phase created, noted here per the checklist. The gitignored local `.env` placeholder was updated the same way.
